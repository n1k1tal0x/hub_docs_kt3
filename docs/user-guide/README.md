## 1 Назначение программы

### 1.1 Функциональное назначение

Программное средство «ФинУчёт» предназначено для автоматизации учёта личных денежных средств
пользователя: хранения сведений о счетах и остатках на них, регистрации финансовых операций
(доход, расход, перевод между счетами), классификации операций по категориям, планирования
и контроля месячных бюджетов, формирования аналитической отчётности за произвольный период.

### 1.2 Эксплуатационное назначение

Программа эксплуатируется на персональном компьютере в однопользовательском режиме.
Все данные хранятся локально; передача сведений в сеть Интернет не выполняется.
Категория пользователей — физические лица, ведущие личный или семейный бюджет и владеющие
Windows на уровне уверенного пользователя. Время освоения по руководству — не более 1 часа.

### 1.4 Ограничения области применения

- работа одного пользователя; одновременный доступ к одному файлу базы данных не поддерживается;
- учёт ведётся в одной валюте, пересчёт по курсам не выполняется;
- программа не предназначена для бухгалтерского и налогового учёта организаций;
- подключение к банковским сервисам не выполняется — данные вводятся вручную или импортируются из CSV;
- гарантированное быстродействие обеспечивается при объёме базы до 50 000 операций.

## 3 Выполнение программы

### 3.1 Установка программы

1. Скопировать каталог с программой на локальный диск.
2. При использовании поставки, зависящей от среды выполнения, установить **.NET 10 Desktop Runtime**.
3. При необходимости создать ярлык `FinUchet.exe` на рабочем столе.

Права администратора не требуются. Удаление выполняется удалением каталога программы;
база данных, копии и журналы остаются в каталоге данных (см. 2.3).

### 3.2 Запуск программы и вход

При запуске автоматически создаётся резервная копия базы данных, после чего открывается окно входа.

![Окно входа в программу](images/01-login.png)
*Рисунок 1 — Окно входа в программу*

1. Ввести пароль в поле **«Пароль»** (для контроля ввода — флажок «Показать пароль»).
2. Нажать **«Войти»** или клавишу `Enter`.

**При первом запуске** окно работает в режиме задания пароля: пользователь вводит новый пароль
и подтверждает его. Пароль хранится только в виде хеша **PBKDF2-HMAC-SHA256** (100 000 итераций,
случайная соль 16 байт) и восстановлению не подлежит. Одновременно справочник категорий
заполняется набором из 24 предустановленных категорий.

После трёх неверных попыток вход блокируется на 60 секунд:

![Сообщение о блокировке входа](images/21-msg-lockout.png)
*Рисунок 2 — Сообщение о блокировке входа*

> ⚠️ Если пароль утрачен, доступ к данным восстанавливается только из резервной копии,
> созданной до изменения пароля (см. [3.11](#311-резервное-копирование-и-восстановление-данных-фт-8)).

### 3.4 Ведение справочника счетов (ФТ-1)

![Раздел «Счета»](images/03-accounts.png)
*Рисунок 4 — Раздел «Счета»*

Текущий остаток рассчитывается автоматически как сумма начального остатка и всех операций
по счёту. Программа поддерживает хранение не менее 50 счетов.

#### Создание счёта

1. Нажать **«Добавить»** — открывается форма «Счёт».
2. Заполнить поля формы.
3. Нажать **«Сохранить»**.

![Форма «Счёт»](images/04-account-dialog.png)
*Рисунок 5 — Форма «Счёт»*

| Поле | Обязательное | Правила заполнения |
|---|:--:|---|
| Наименование | да | 1…100 символов, должно быть уникальным |
| Тип счёта | да | «Наличные», «Банковская карта», «Банковский счёт», «Вклад» |
| Валюта | да | Код по ИСО 4217; по умолчанию — валюта из настроек |
| Начальный остаток | да | Число с двумя знаками после запятой |
| Цвет в списке | нет | Цвет метки счёта в таблицах |
| Архивный счёт | нет | Архивные счета не предлагаются при регистрации операций |

#### Изменение, архивирование и удаление

- **«Изменить»** (или двойной щелчок по строке) — правка счёта; изменение начального остатка
  пересчитывает текущий остаток.
- **«В архив»** — счёт сохраняется вместе с операциями, но исчезает из списков выбора.
- **«Удалить»** — удаление счёта, по которому есть операции, блокируется:

![Сообщение об отказе в удалении счёта](images/05-msg-account-delete.png)
*Рисунок 6 — Сообщение об отказе в удалении счёта*

### 3.5 Ведение справочника категорий (ФТ-3)

![Раздел «Категории»](images/06-categories.png)
*Рисунок 7 — Раздел «Категории»*

Справочник двухуровневый: категория → подкатегория. Переключение между расходами и доходами —
кнопками над таблицей.

1. **«Добавить»** — категория первого уровня: наименование, тип («Доход»/«Расход»), цвет для диаграмм.
2. **«Подкатегория»** — создаётся для выбранной категории и наследует её тип.
3. **«Изменить»** — правка выбранной категории.
4. **«Удалить»** — блокируется, если категория используется в операциях или бюджетах.

Категории третьего уровня не предусмотрены.

### 3.6 Регистрация финансовых операций (ФТ-2)

![Раздел «Операции»](images/07-operations.png)
*Рисунок 8 — Раздел «Операции»*

#### 3.6.1 Доход и расход

1. Нажать **«Расход»** (или **«Доход»**) — открывается форма «Операция».
2. Заполнить поля формы.
3. Нажать **«Сохранить»** либо **«Сохранить и создать»** для ввода следующей операции.

![Форма «Операция», тип «Расход»](images/08-operation-expense.png)
*Рисунок 9 — Форма «Операция», тип «Расход»*

| Поле | Обязательное | Правила заполнения |
|---|:--:|---|
| Тип операции | да | «Доход», «Расход» или «Перевод» |
| Дата | да | Не позже текущей даты |
| Сумма, ₽ | да | Строго больше нуля, два знака после запятой |
| Счёт | да | Счёт зачисления (доход) или списания (расход) |
| Счёт-источник / получатель | да (для перевода) | Счета не должны совпадать |
| Категория | да (доход, расход) | Из справочника соответствующего типа |
| Подкатегория | нет | Из подкатегорий выбранной категории |
| Комментарий | нет | До 255 символов |

#### 3.6.2 Перевод между счетами

![Форма «Операция», тип «Перевод»](images/09-operation-transfer.png)
*Рисунок 10 — Форма «Операция», тип «Перевод»*

Категория для перевода не указывается. Перевод записывается **в одной транзакции**: остатки
обоих счетов изменяются одновременно, при ошибке транзакция полностью отменяется.

#### 3.6.3 Контроль вводимых данных

Поле, заполненное неверно, выделяется красной рамкой, под ним выводится пояснение,
операция не сохраняется:

![Сообщение о недопустимой сумме операции](images/10-msg-amount.png)
*Рисунок 11 — Сообщение о недопустимой сумме операции*

#### 3.6.4 Изменение и удаление операции

**«Изменить»** / **«Удалить»** — для выбранной строки. Остатки по счетам и показатели
исполнения бюджетов пересчитываются автоматически.

### 3.7 Поиск и фильтрация операций (ФТ-4)

Условия фильтра объединяются по правилу «И».

| Условие | Описание |
|---|---|
| Период с … по … | Дата начала не должна быть позже даты окончания |
| Счёт | Один счёт или все счета |
| Тип операции | «Доход», «Расход», «Перевод» или все типы |
| Категория | При выборе категории 1 уровня в отбор входят её подкатегории |
| Текст комментария | Вхождение подстроки, регистр не учитывается |

1. Задать условия отбора.
2. Нажать **«Применить»** — результат выводится постранично, по 50 записей.
3. Переход по страницам — кнопками **«Назад»** и **«Далее»**.
4. **«Сбросить»** — отмена всех условий.

Под таблицей выводятся итоги по отбору и время формирования результата: на базе
в 50 000 операций отбор занимает не более 2 с.

### 3.8 Планирование и контроль бюджетов (ФТ-5)

![Раздел «Бюджеты»](images/11-budgets.png)
*Рисунок 12 — Раздел «Бюджеты»*

1. Выбрать месяц в поле **«Месяц»**.
2. Нажать **«Задать лимит»**, выбрать категорию расходов и указать сумму.
3. Нажать **«Сохранить»**.

| Исполнение лимита | Индикатор | Действия программы |
|---|:--:|---|
| менее 80 % | 🟢 зелёный | сообщения не выводятся |
| от 80 % до 100 % | 🟡 жёлтый | предупреждение о приближении к лимиту |
| более 100 % | 🔴 красный | предупреждение о превышении лимита |

![Предупреждение о превышении лимита бюджета](images/12-msg-budget.png)
*Рисунок 13 — Предупреждение о превышении лимита бюджета*

Предупреждение информационное: операция сохраняется, решение принимает пользователь.
Кнопка **«Копировать месяц»** переносит набор лимитов на следующий месяц.

2. Задать период и, при необходимости, счёт.
3. Нажать **«Сформировать»**; для печати — **«Печать»**.

![Отчёт «Доходы и расходы за период»](images/13-report-totals.png)
*Рисунок 14 — Отчёт «Доходы и расходы за период»*

*Рисунок 15 — Отчёт «Структура расходов по категориям»*

### 3.10 Экспорт и импорт данных (ФТ-7)

![Раздел «Сервис»](images/16-service.png)
*Рисунок 17 — Раздел «Сервис»*

Формат обмена — CSV: кодировка UTF-8, разделитель «точка с запятой», структура по RFC 4180
(см. [приложение Б](#приложение-б-структура-файла-обмена-csv)).

#### Экспорт

1. В разделе «Операции» задать отбор и нажать **«Применить»**.
2. В разделе «Сервис» нажать **«Обзор…»** и указать файл.
3. Нажать **«Экспортировать»**.

#### Импорт

1. Нажать **«Обзор…»** и выбрать файл.
2. Нажать **«Импортировать»**.
3. Изучить протокол импорта.

![Окно «Протокол импорта»](images/17-import-log.png)
*Рисунок 18 — Окно «Протокол импорта»*

Строки с ошибками не импортируются; по каждой выводится номер строки и причина отклонения.
Корректные строки загружаются независимо от наличия ошибочных.

### 3.11 Резервное копирование и восстановление данных (ФТ-8)

Копия создаётся автоматически при каждом запуске; хранятся 5 последних копий.

- **«Создать копию»** — копия вручную в указанный файл (рекомендуется не реже раза в месяц на внешний носитель).
- **«Восстановить»** — восстановление из выбранной копии с подтверждением:

![Запрос подтверждения восстановления данных](images/18-msg-restore.png)
*Рисунок 19 — Запрос подтверждения восстановления данных*

> ⚠️ **Внимание!** При восстановлении текущее состояние базы данных полностью заменяется
> содержимым копии. Изменения, внесённые после её создания, будут утрачены.
> После восстановления программа перезапускается.

### 3.12 Настройка параметров программы (ФТ-10)

![Раздел «Настройки»](images/19-settings.png)
*Рисунок 20 — Раздел «Настройки»*

- **Общие параметры** — валюта по умолчанию, формат даты, режимы запуска.
- **Оформление интерфейса** — светлая или тёмная тема с предварительным просмотром.
- **Безопасность** — смена пароля: текущий пароль, новый пароль и его повтор.
- **О программе** — версия, платформа, файл базы данных, вызов руководства и каталога данных.

Заданные значения сохраняются автоматически и действуют при следующих запусках.

### 3.13 Завершение работы программы

- меню **«Файл» → «Выход»**;
- кнопка закрытия окна;
- сочетание клавиш `Alt+F4`.

Операции сохраняются в момент их регистрации, поэтому отдельного сохранения при выходе
не требуется. Если открыта форма с незавершённым вводом, программа запросит подтверждение.

## 4 Сообщения пользователю

### 4.1 Виды сообщений

| Вид | Значок | Смысл |
|---|:--:|---|
| Ошибка | 🔴 | Действие не выполнено, требуется исправление данных |
| Предупреждение | 🟡 | Действие выполнено, но требует внимания |
| Информационное | 🟢 | Действие выполнено успешно |
| Запрос подтверждения | 🔵 | Требуется решение пользователя |

Ошибки заполнения полей выводятся под полем ввода, поле выделяется красной рамкой.
При непредвиденной ошибке программа **не завершается аварийно**: работа продолжается,
технические сведения записываются в журнал.

![Сообщение о непредвиденной ошибке](images/20-msg-unhandled.png)
*Рисунок 21 — Сообщение о непредвиденной ошибке*

### 4.3 Сообщения журнала работы

Журналы ведутся в каталоге `logs` с ежедневной ротацией, срок хранения — 14 суток.

| Уровень | Пример записи | Значение |
|---|---|---|
| `INF` | `Запуск приложения 1.0.0` | Штатное событие |
| `INF` | `Резервная копия создана` | Создана автоматическая копия БД |
| `INF` | `Миграции БД: 0 новых` | Проверена схема базы данных |
| `WRN` | `Лимит «Развлечения»: 116 %` | Превышение лимита бюджета |
| `ERR` | `Ошибка доступа к файлу базы данных` | Ошибка, о которой выведено сообщение |

При обращении к разработчику следует приложить файл журнала за день возникновения ошибки.

## Приложение Б. Структура файла обмена CSV

Кодировка UTF-8, разделитель полей — `;`, разделитель строк — CRLF, оформление по RFC 4180.
Первая строка содержит заголовки колонок.

| № | Колонка | Тип | Описание | Пример |
|:--:|---|---|---|---|
| 1 | `date` | Дата | Дата операции, ИСО 8601 | `2026-09-23` |
| 2 | `type` | Строка | `income`, `expense`, `transfer` | `expense` |
| 3 | `amount` | Число | Сумма, два знака после запятой | `2340.00` |
| 4 | `account` | Строка | Счёт (для перевода — источник) | `Карта «Мир» •4417` |
| 5 | `account_to` | Строка | Счёт-получатель (только для перевода) | `Накопительный счёт` |
| 6 | `category` | Строка | Наименование категории | `Продукты` |
| 7 | `subcategory` | Строка | Наименование подкатегории | `Супермаркеты` |
| 8 | `comment` | Строка | Комментарий, до 255 символов | `Магазин «Пятёрочка»` |

```csv
date;type;amount;account;account_to;category;subcategory;comment
2026-09-23;expense;2340.00;Карта «Мир» •4417;;Продукты;Супермаркеты;Магазин «Пятёрочка»
2026-09-21;income;96000.00;Карта «Мир» •4417;;Заработная плата;;Аванс за сентябрь
2026-09-19;transfer;10000.00;Наличные;Накопительный счёт;;;Пополнение накоплений
```
